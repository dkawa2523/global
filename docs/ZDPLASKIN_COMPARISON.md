# ZDPlaskin Comparison Notes

## Scope

Repository: `https://github.com/Hemadityamalla/ZDPlaskin`

This repository includes an isolated local parity case for ZDPlaskin
`example2`. The purpose is simple: put this code on the same practical input
footing for that public Ar DC-resistor discharge and check whether the final
power, E/N, and species composition agree.

The comparison uses the committed ZDPlaskin output file because this Windows
environment does not provide the Linux `.so` libraries and Fortran toolchain
needed to rerun ZDPlaskin directly.

## Files

- chemistry bundle: `examples/chemistry_zdplaskin_example2`
- chamber: `examples/configs/chamber_zdplaskin_example2.yaml`
- recipe: `examples/configs/recipe_zdplaskin_example2.yaml`
- case: `examples/configs/case_zdplaskin_example2.yaml`
- output: `examples/outputs/zdplaskin_example2_surrogate`
- comparison tool: `tools/external_benchmarks/zdplaskin_example2.py`
- same-footing report: `tools/external_benchmarks/same_footing_assessment.py`

The active E/N-rate table is generated from the committed ZDPlaskin output:

```powershell
py tools\external_benchmarks\build_zdplaskin_output_rate_table.py
```

This table reverse-engineers the saved ZDPlaskin reaction-rate columns into
rate coefficients on the saved E/N grid. That is the cleanest way to compare
this local ODE/circuit implementation against the saved ZDPlaskin run without
pretending that the local two-term solver is identical to ZDPlaskin/BOLSIG+.

## What Is Matched

- gas: Ar
- species family: `e`, `Ar`, `Ar*`, `Ar+`, `Ar2+`
- pressure: 100 torr, represented as about `1.333e4 Pa`
- gas temperature: `300 K`
- gap: `0.004 m`
- radius/area/volume from ZDPlaskin example2
- source voltage: `1000 V`
- ballast resistance: `100 kOhm`
- electron-impact rate coefficients: output-derived E/N-rate table
- Ar* de-excitation/superelastic channel: output-derived E/N-rate table
- ion wall/diffusion loss: first-order ZDPlaskin-style benchmark setting

The local code still uses its own Python solver, state layout, diagnostics,
and internal `dc_series_circuit` backend.

## Current Result

Run:

```powershell
py -m plasma_global.cli run examples\configs\case_zdplaskin_example2.yaml
py tools\external_benchmarks\run_external_benchmarks.py --only zdplaskin
py tools\external_benchmarks\same_footing_assessment.py --skip-runs
```

The saved transient peak electron density is not identical:

- local peak: about `3.22e17 m-3`
- ZDPlaskin saved peak: about `3.57e17 m-3`
- ratio: about `0.90`

That is acceptable for this parity target because the comparison is based on
final operating state, not full time-history identity.

## Why It Previously Did Not Match

The mismatch was not one single physics failure.

1. The local generated HDF5 field table had a sorting bug for field-gridded
   tables. A descending or nonmonotonic E/N source could keep rates and field
   coordinates out of sync.
2. The old local table was generated by this repository's simplified two-term
   workflow from cross sections. That is useful physics, but it is not the
   same as the saved ZDPlaskin/BOLSIG+ rate history.
3. The earlier wall-loss setup used the local wall-loss family rather than the
   first-order diffusion-loss behavior used by the ZDPlaskin example.
4. The Ar* de-excitation/superelastic path was previously approximate instead
   of coming from the ZDPlaskin output-derived E/N table.

The current benchmark fixes those comparison-specific issues without folding
ZDPlaskin-specific logic into the core solver.

## Interpretation

For this ZDPlaskin example2 parity case, the code can reproduce the final
single-volume DC discharge state when it is given the same effective rate
history and matching benchmark loss/circuit settings.

This does not prove general production accuracy for unrelated Ar ICP/CCP/RF
cases, other pressures, gas mixtures, surface kinetics, or pulsed operation.
Those still need separate benchmark cases.
